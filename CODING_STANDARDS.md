# Coding Standards

Conventions for code in this repo. Anything ruff, mypy or pre-commit already enforces is left to
the tooling and not repeated here.

## Architecture

- Group code **by feature**: `src/agrobot/<feature>/{router,service,repository,models,schemas}.py`.
  - `router` is HTTP only and thin. `service` holds business logic and imports nothing from
    FastAPI. `repository` holds the SQLAlchemy queries.
- Inject dependencies (FastAPI `Depends`, constructor args) rather than importing module-level
  globals.
- Put external side effects behind a `Protocol` port (e.g. a `Notifier`) with concrete adapters.
  ORM models double as domain objects — there is no entity ↔ ORM mapping layer.
- Register every feature's models in `src/agrobot/models.py`. Alembic autogenerate and the
  migrations-in-sync test only see models imported there.

## Async

All I/O is async: `async def` endpoints, `AsyncSession`, the async worker. Reach for async
libraries (asyncpg, `httpx.AsyncClient`, `asyncio.sleep`) whenever code waits on the network,
disk or clock.

## Persistence

- **Transactions**: the request session never auto-commits; services call `commit()` explicitly.
- **Models** inherit `Base` and use `UUIDPrimaryKeyMixin` (UUIDv7 PKs generated by Postgres `uuidv7()`) and `TimestampMixin`
  (`timestamptz` `created_at`/`updated_at`), with typed `Mapped[...]` columns.
- **Datetimes** map to `timestamptz`; create them timezone-aware in UTC (`datetime.now(UTC)`).
- **Migrations**: generate with Alembic autogenerate, then review the file by hand. Constraint
  names come from the naming convention in `core/db.py`, so leave them unnamed in models and
  migrations. Every migration ships a working `downgrade`.

## Config

Settings come from env vars via `Settings` (`core/config.py`). A new variable goes into
`Settings` and `.env.example` together.

## Logging

Use `structlog.get_logger(__name__)`. Event names are `area.event` with the details as key/value
context:

```python
logger.info("orders.created", order_id=order.id, total=order.total)
```

## Typing

mypy strict covers `src`, `tests` and `migrations`; tests are typed like production code.

## Testing

- Tests run against real Postgres via testcontainers, on the same `postgres:18` image as
  `compose.yaml`.
- Migrations run once per session using the real Alembic scripts, so the test schema is exactly
  the migrated schema.
- `db_session` wraps each test in a transaction rolled back at the end, with
  `join_transaction_mode="create_savepoint"` — code under test can `commit()` freely.
- `client` is an `httpx.AsyncClient` against the app with `get_session` overridden to
  `db_session`.
- `tests/test_migrations.py` fails when models and migrations drift or a downgrade breaks.
- pytest-asyncio runs in auto mode on a session-scoped loop: write plain `async def test_...`.

## Language

Code, identifiers, comments, docs and the README are in English. Only `docs/TASK.md`, the
original task statement, is in Spanish.
